Alerta Nova — AWS Serverless IoT Architecture

Designed and implemented a cloud backend architecture for an IoT-connected product using AWS serverless services, then decomposed the platform into independently deployable infrastructure stacks with automated CI/CD.

02 / Decomposition

From monolith to deployable service stacks

The backend evolved from a large SAM/CloudFormation definition into multiple stacks aligned to clear responsibilities. This reduced deployment coupling and made individual parts of the cloud system easier to build, test, and release.

  • IoT ingestion and device-state processing
  • AppSync GraphQL API and authorization
  • System processes and scheduled routines
  • Web-application backend services
  • Monitoring / backup / supporting infrastructure
  • Pipeline and deployment infrastructure
03 / API architecture

GraphQL with direct data access where appropriate

AppSync

GraphQL API for device status, messages, data, connectivity, timezone, routines, and web-app jobs.

Authorization

Lambda-based authorization integrated with external identity validation, alongside IAM and API-key modes.

Resolvers

JavaScript resolver functions use direct DynamoDB data sources for low-overhead reads and writes, reserving Lambda for integration logic.

04 / Event-driven behavior

Serverless processing and scheduling

01IoT message arrives

AWS IoT rules route selected telemetry and status topics into Lambda processing.

02Lambda evaluates the event

Functions perform ingestion, state updates, notification/routine logic, or time-series storage.

03State is persisted

DynamoDB holds operational state while Timestream supports time-series telemetry.

04Applications consume state

AppSync and REST endpoints expose backend data and actions to application clients.

05Scheduled work runs independently

EventBridge schedules and events trigger periodic or lifecycle-related backend processes.

06 / Engineering takeaways

Why this matters for systems engineering

  • Architecture decomposition: split a large cloud system into logical service boundaries and deployment units.
  • Interface definition: defined device-to-cloud, event, API, and database interfaces.
  • Fault containment: serverless functions and service boundaries isolate processing responsibilities and deployment failures.
  • Traceable infrastructure: infrastructure-as-code makes architecture changes reviewable and repeatable.
  • Verification: service-level tests, deployment checks, and CI/CD provide evidence that infrastructure and integrations behave as intended.
